# New pages

## New page vs optimize
Optimize when a live page already owns the intent (or can). Build new when: the keyword cluster has no page (for example a survey cluster of about 320 combined volume with no page); an audience segment searches differently; a high-value query pattern needs its own page (one per integration partner). Never create a second page for a term an existing landing page owns.
Run the brief first (references/page-optimization.md, Page Type = New Page), then build.

## Section pattern (use-case page)
1 Hero: eyebrow, H1, sub, primary CTA, secondary anchor naming the centerpiece, optional note under buttons.
2 Problem: H2 phrased as a customer pain sentence; 3 to 5 paragraphs, one bolded line.
3 Centerpiece (anchor target): the process as steps, tracks, phases or stages.
4 How the product delivers it (H3 per capability, each linking its page).
5 Built to work with the customer's existing system (integrations), where relevant.
6 Proof: 3 to 4 stat cards, each linking a named case study (allow-list only).
7 FAQ: H2 "Questions About ...", 5 to 7 questions as H3, mirrored as FAQPage JSON-LD.
8 CTA: short imperative H2, primary CTA, secondary link to an adjacent page.
Add FAQs for keyword coverage.

## Hub and audience pages
Hub: hero > problem > core idea (each pillar linking its page) > strategy > what we do vs what adjacent tools do > audience cards > proof > FAQ > CTA. JSON-LD: WebPage, FAQPage, BreadcrumbList.
Audience page: breadcrumb hero > problem reframed for the audience > segmentation > two topic sections tied to the audience's jobs > results > FAQ > CTA to the hub, conversion page and a related use case.
Rule: every body section links to the page or case study it summarizes, with keyword anchor text. Each audience page links up to the hub and sideways to its sibling. Breadcrumb Home > Hub > page.

## Placement rule
Decide the nav placement in the profile. Ship nav items hidden until HEAD requests to every new path return 200, so there are never dead links. Every new page is linked from nav, a body section and the sitemap.

## Integration pages
One page per integration partner, target "<product category> that integrates with <partner>". Include walkthrough, case study, what writes back and what does not. Claim only what is true.

## Templated section library (for fast builds)
Hero (centered with CTAs; split with form); social proof (static logo bar, stats bar, single large testimonial, case-study card); features (50/50 image-text left and right, 4-column icon grid, product screenshot, comparison table, how-it-works 3 steps, unique feature); conversion (full-width banner, split banner, contact form, demo form, newsletter bar, pricing tiers); content (FAQ accordion, blog card grid); integrations (scrolling logo bar, grouped "works with your stack"); team and company (bio page, values grid, mission and vision, timeline). 15 to 17 sections are enough; new pages are copy-paste builds. Every section is native HTML.
